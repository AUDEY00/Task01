# Task 9 – Document Editor

## Task Description

Implement a document editing feature within the AngularJS Management System using Quill.js. The task focuses on saving the generated HTML document content to Firebase Firestore, providing a separate Preview Mode for displaying the formatted content, and implementing automatic draft saving.

---

## Subtasks

### Subtask 1 – Firebase HTML Payload and Preview Mode

Save the generated HTML payload directly into Firebase and create a separate Preview Mode that renders the stored HTML content using AngularJS `$sce` (Strict Contextual Escaping).

### Subtask 2 – Auto-Save

Implement an auto-save feature that saves the document to Firebase after 10 seconds of typing inactivity while displaying a small **"Saving draft..."** indicator.

---

# 1. Firebase HTML Payload and Preview Mode

## Implementation

The Quill.js editor generates formatted HTML content from the document.

The generated content is stored in:

```javascript
vm.documentContent
```

The HTML payload is then saved to Firebase Firestore inside the `documents` collection.

Example document structure:

```text
documents
│
└── doc_<generated-id>
    │
    ├── content
    ├── dateCreated
    └── dateModified
```

The `content` field contains the HTML generated by Quill.js, allowing the document's formatting to be preserved.

---

## Preview Mode

A separate Preview Mode was implemented to allow users to view the formatted document without editing it.

The stored HTML content is passed through AngularJS `$sce` before being rendered:

```javascript
vm.previewContent =
    $sce.trustAsHtml(vm.documentContent);
```

The preview displays the formatted HTML generated by Quill.js, including headings, lists, text formatting, colors, and alignment.

The Preview Mode also provides a **Back to Editor** action so users can return to the editing interface.

> **Note:** `$sce.trustAsHtml()` tells AngularJS to trust the provided HTML for rendering. It should only be used with HTML content that is controlled or properly validated by the application.

---

# 2. Auto-Save Feature

## Implementation

An automatic draft-saving mechanism was implemented to reduce the risk of losing document changes.

The system listens for changes in the Quill.js editor using the `text-change` event.

Whenever the user types, the existing auto-save timer is cancelled and restarted.

The document is automatically saved after **10 seconds of typing inactivity**.

```text
User types
    ↓
Reset auto-save timer
    ↓
User continues typing
    ↓
Reset timer again
    ↓
User stops typing
    ↓
10 seconds
    ↓
Save draft to Firebase
```

---

## Saving Indicator

While the document is being saved, the interface displays a small status indicator:

```text
Saving draft...
```

The indicator includes a loading spinner to provide visual feedback without interrupting the user's editing experience.

After the Firebase operation finishes, the indicator is automatically hidden.

---

## Existing Document Updates

If the document already has a Firebase document ID, the auto-save feature updates the existing Firestore document rather than creating a duplicate.

```javascript
db.collection("documents")
    .doc(vm.documentId)
    .update(documentData)
```

If no document ID exists yet, the system creates a new document and stores the generated ID for future auto-save operations.

This allows subsequent auto-saves to continue updating the same document.
